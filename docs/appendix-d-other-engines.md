# Appendix D: Other Engines

The architecture of `docs/03-architecture.md` is engine-neutral; the templates are written for Unity with MelonLoader or BepInEx. This appendix maps the pieces onto other engines. Reconnaissance for non-Unity games: `docs/02-reconnaissance.md`, "Engine-neutral minimum".

## What stays the same everywhere

- One AccessibilityMgr with one current screen and a stack of UIs; only the focused component gets keys and voice.
- One accessible class per game surface, opened and closed by the game's own events.
- Keys declared once with exact modifiers.
- Every spoken text localized, the game's own strings first, English fallback, tab-separated text files.
- Every call from the game into the mod guarded; missing game members reported, not fatal.
- Decompiled or extracted game code in a private git repository, one branch per game version.
- Tolk (or the platform's equivalent) for speech.

## What changes per engine

For each engine: how mod code gets in, what a "hook" is, how to read keys, how to detect the language.

### Unity (Mono or IL2CPP)

- Code in: MelonLoader or BepInEx (`docs/appendix-a-unity-loaders-harmony.md`). IL2CPP: interop assemblies generated by the loader; decompile those (`docs/01-setup-and-tooling.md`, Step 7).
- Hooks: Harmony Prefix and Postfix.
- Keys: `UnityEngine.Input` or the Input System package (appendix A).
- Language: the game's own localization manager; `Application.systemLanguage` only as last resort.

```csharp
string lang = Language.getAlias();                         // a game's own class (example)
string lang = PlayerPrefs.GetString("language", "en");     // stored preference
SystemLanguage sys = Application.systemLanguage;           // last resort
```

- When to initialize: the loader's init, or the first scene load if early access crashes (appendix A).

### Other .NET games (XNA, FNA, MonoGame, custom C# engines)

- Code in: BepInEx (it supports several non-Unity .NET runtimes), a custom loader, or a patched entry assembly. Check the game's modding community first.
- Hooks: Harmony works on any .NET runtime the loader supports.
- Keys: the framework's keyboard state (`Keyboard.GetState().IsKeyDown(Keys.F1)` in XNA/MonoGame); AccessibleKey compares with the previous frame's state to get "pressed this frame".
- Decompile with ilspycmd like Unity; `scripts/Decompile-Game.ps1 -GamePath <folder with the DLLs>`.

### Godot

- Godot 4 with C# (.NET): mod code can be loaded as an additional assembly by some community loaders; Harmony then works on the game's C# code. GDScript games: mods are scripts loaded through the game's own mod support or a PCK patch; "hooks" are signals the mod connects to, or replaced scripts.
- Extract: PCK files with a Godot RE tool (GDRE Tools) to get scenes and scripts.
- Screens: Godot scenes and `Control` nodes; connect to `visibility_changed`, `tree_entered`, `tree_exiting` of the panel nodes as open and close events.
- Keys: `Input.IsActionJustPressed` or `_UnhandledInput` with `InputEventKey`.
- Language:

```csharp
string locale = TranslationServer.GetLocale();   // "en_US"
string lang = locale.Substring(0, 2);            // "en"
```

```gdscript
var locale = TranslationServer.get_locale()
```

- The game's own strings: `Tr("KEY")` / `tr("KEY")`.
- When to initialize: `_Ready()` of the mod's main node.
- Speech: Tolk through P/Invoke from C#, or a GDExtension for GDScript-only games.

### Unreal Engine

- Code in: UE4SS (Lua and C++ mods) or a proxy DLL; Blueprint-only games through UE4SS Blueprint mods.
- Extract: FModel or UModel for assets; UE4SS dumps the class and property structure (SDK headers, "Live View").
- Hooks: UE4SS `RegisterHook("/Script/Module.Class:Function", ...)` on UFunctions (open and close of UMG widgets: `Construct`, `Destruct`, `AddToViewport`, `RemoveFromParent`, the game's own Show and Hide functions).
- Screens: UMG widgets; read text from `TextBlock` properties.
- Keys: hook the player controller's input, or UE4SS `RegisterKeyBind`.
- Language:

```cpp
FString Culture = FInternationalization::Get().GetCurrentCulture()->GetName();   // "de-DE"
```

  or `UKismetInternationalizationLibrary::GetCurrentLanguage()`.
- When to initialize: after the game module is up (UE4SS mod start, or `PostInitializeComponents` of a hooked actor).
- Speech: Tolk loaded from the C++ mod, or a small native bridge called from Lua.

### Custom native engines (C++)

- Code in: DLL injection or a proxy DLL (`dinput8.dll`, `version.dll`), with a hooking library (MinHook, Detours).
- Extract: Ghidra or IDA; strings and symbol names lead to UI code. Reconnaissance is much slower; the slice workflow keeps it bounded.
- Hooks: function detours on the UI's open, close and text-draw functions.
- Text: often the most reliable source is the game's text-drawing or localization lookup function; hook it to learn which strings belong to which screen.
- Speech: Tolk directly (it is a C library).

### Web-based games (Electron, browser)

- Many already expose HTML; check whether the game's DOM is reachable by the screen reader before modding.
- Code in: a preload script or an injected userscript.
- Hooks: DOM mutation observers on the game's panels, or wrapping the game's JavaScript functions.
- Speech: ARIA live regions, which the screen reader reads itself, instead of Tolk.

## Mapping the core classes

- **AccessibilityMgr**: the same class in the engine's language (C#, Lua, GDScript, C++). It needs a per-frame update (the engine's tick, a Lua loop hook, `_Process`).
- **AccessibleComponent**: the same three methods.
- **Hooks**: whatever the engine offers as "this panel was opened by the game": Harmony postfix, signal, UFunction hook, detour. Always guarded (pcall in Lua, try-catch in C#/C++).
- **AccessibleKey**: wraps the engine's key state; same exact-modifier rule.
- **LocalizationUtils**: the same tab-separated files; read them from the mod folder if the engine cannot embed resources.
- **Compat**: report every hook that could not be installed and every member lookup that failed; speak the count at startup.
- **Tests**: the localization checks only parse the text files and the key declarations, so they adapt easily to a mod in another language (change the regex that finds keys); the game-compatibility test is .NET-only, so other engines keep a list of hook targets in `docs/game-api.md` and re-check it against each new decompiled or dumped version.
